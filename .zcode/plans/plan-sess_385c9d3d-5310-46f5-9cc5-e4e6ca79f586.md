## Force translation design

Add an explicit opt-in force mode named `force_translate`.

### Configuration and API

- Add `force_translate: bool = False` to `TrimConfig`.
- Keep the default safe behavior unchanged: `translate_enabled=True` still accepts a translation only when it is strictly cheaper under the selected counter.
- Preserve `enabled_stages` precedence. A configured stage list still controls whether translation runs.
- Extend `translate_stage()` and its internal helper with a trailing `force=False` parameter so existing positional callers remain compatible.
- Pass `force=config.force_translate` from the pipeline.

### Safety behavior

Force mode will bypass only the final token-size comparison. It will still reject:

- translator exceptions;
- empty output;
- dropped URL placeholders;
- malformed line counts;
- protected fence/custom-pattern lines being sent for translation.

A forced translation may increase the translation stage’s token count. Pruning will still use the original-input budget afterward.

### CLI

- Add `--force-translate` to both `trim` and `report` subcommands.
- Make the flag imply translation, so users can run `--force-translate` without also specifying `--translate`.
- Set `force_translate=args.force_translate` in `_config_from_args()`.
- Leave ordinary `--translate` behavior unchanged.

### Tests

- Add a direct translation test showing an inflated translation is rejected normally but accepted with `force=True`.
- Add tests proving forced mode still rejects dropped placeholders, malformed line structure, and translator failures.
- Add pipeline coverage for `TrimConfig(force_translate=True)` and default-off behavior.
- Add CLI coverage for `--force-translate` and report mode.
- Run the full suite and syntax/diff checks.

### Documentation

Update both `README.md` and `README.zh-CN.md` with:

- the `--force-translate` command example;
- the Python `TrimConfig(force_translate=True)` example;
- the configuration table entry;
- an explicit warning that force mode may increase token count or change semantics;
- a clarification that structural/protected-output validation still applies.

No changes will be made to unrelated root-level CLI behavior or the existing Argos model setup flow.
